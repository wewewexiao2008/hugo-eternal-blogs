## 为什么要搭模拟器

交易模拟器是量化理解的期末考试，因为它强迫所有概念共存。忽略滑点的回测会爱上你的动量策略；忽略回撤的仓位模型会在爆掉之前一直显得聪明；年化口径错了的分析层会把你 0.3 的 Sharpe 报成 3。模拟器给每个偷懒行为照镜子。

这里也有 Jane Street 的影子。他们的实习项目包含模拟交易环节——实时对着模拟市场交易，教官扮演对手方。他们的交易员整天活在工具里。Signals & Threads 播客的 "Building Tools for Traders with Ian Henry" 一期讲的就是给期权台"以微秒计量时间"的交易员写软件；"From the Lab to the Trading Floor with Erin Murphy" 讲研究如何走向生产。在这样的公司，"先模拟"从来就是文化本身，而非学术练习。

于是我搭了一个。Python，约 800 行，除 NumPy 外零依赖。

## 架构

```
MarketData → SignalEngine → RiskManager → ExecutionEngine → PortfolioTracker
                                                              ↓
                                                    PerformanceAnalyzer
```

每一层只负责一个决策，而层与层之间的接口就是交易业务的实际决策：

- **MarketData**：世界在做什么（价格、价差、深度、成交量）
- **SignalEngine**：我们相信什么（[-1, 1] 区间的方向观点）
- **RiskManager**：该押多少（给定信号、净值、波动率、回撤下的仓位）
- **ExecutionEngine**：行动的代价（成交、滑点、佣金、冲击）
- **PortfolioTracker**：我们拥有什么（现金、持仓、按市值计价的净值）
- **PerformanceAnalyzer**：这一切意味着什么（风险调整收益、回撤、尾部）

分层很关键。当信号、仓位、执行挤在一个函数里，你没法问"亏钱是因为信号错了、仓位错了、还是成交太贵？"流水线让这个问题变得可问。

## 行情数据：合成但不天真

生成器用几何布朗运动加随机波动率推演中间价（波动率本身受冲击，钳在 [5%, 80%]），按 tick 取整，围绕它报出 5 个基点价差的买卖盘。深度是每边五档，档位规模服从指数分布。日内成交量遵循真实市场的 U 型——开盘和收盘大约翻倍。

执行成本用平方根市场冲击模型：冲击 ∝ σ·√(下单量/日均成交量)。这是微观结构文献里的"平方根定律"，标准参考是 Almgren 等人的 *Direct Estimation of Equity Market Impact*（2005），最优执行问题本身则追溯到 Almgren 与 Chriss（2000）。微观结构背景见 Harris 的 *Trading and Exchanges*（[第6期](how-to-enter-jane-street-ep6.md)）。

```python
def get_market_impact(self, order_size: float) -> float:
    adv = np.mean(self.volume_history[-20:])
    impact_bps = self.sigma * np.sqrt(order_size / adv) * 10000
    return impact_bps / 10000
```

## 信号：三个玩具和一个组合问题

我注册了三个刻意简单的策略：20 周期动量、50 周期均值回归、布林带式波动率突破。各自输出 [-1, 1] 的信号，引擎按权重（0.40 / 0.35 / 0.25）合成。

这对应真实交易台最难的问题：alpha 组合。单独看几乎一无所知的信号，必须聚合成一个仓位建议，而聚合权重本身就是建模决策。

## 风险：四分之一凯利、波动率目标、回撤节流

风险管理器用四层把信号转成仓位：

1. **波动率目标**：按*资产*的已实现波动率，把仓位缩放到年化 15% 的目标。（为什么加星号，后面说。）
2. **凯利式仓位**：名义本金 ∝ 净值 × |信号| × 0.25。四分之一凯利——全凯利只在你的优势估计正确时最优，而它从来不会正确。Kelly 1956 年的论文是源头文献；实践教训是分数凯利用增长换生存。
3. **回撤节流**：从回撤限额的一半开始线性降杠杆，到限额（这里 10%）降为零。在流血？做小。到限？空仓。
4. **硬性仓位上限**：±1,000 股，没有例外。

## 执行与分析：诚实居住的地方

市价单穿越价差，付 2 个基点滑点加每股 $0.005 佣金。成交量上限约束在可用量的 10%——参与率限制，你没法假装一分钟买一百万股。

分析层算 Sharpe、Sortino、Calmar、最大回撤及时长、胜率、盈亏比、95/99 分位 VaR。有个口径至关重要：模拟器按分钟步进（每年 252 天 × 390 分钟），所以所有年化必须用 252 × 390 的周期数。把分钟级收益流和按日年化因子混在一起，会悄悄腐蚀每一个缩放后的指标。

## 然后我找到了那些 Bug

第一次完整跑出来的结果看起来挺像样。基线：5,000 周期 -0.77%，最大回撤 -9.61%，359 笔成交。场景分析甚至有个故事：闪崩场景打出 +26.55%，"均值回归在恐慌中收钱"。这句话差点就写进这篇博客了。

结果我去探测了一个函数。场景表里正常市场的回合胜率是 0.0%——每一分钟都非正——而总收益（-15.33%）和最大回撤在基点级别相等。单调流血、零盈利分钟的签名非常特定。于是我手工对 `Position.update_fill` 做单元测试：

```python
pos.update_fill(Side.BUY, 10, 100.0)
# quantity == 0.0  <-- 买了 10 股之后依然是空仓
```

**Bug 1，最大的那个。** `update_fill` 的开仓分支是：

```python
if self.quantity == 0:
    self.avg_price = price
elif ...  # 加仓
else:     # 减仓
```

`if` 分支设完 `avg_price` 就走完了整条链——它从来没给 `quantity` 赋值。Python 的 `if/elif/else` 是一条语句，命中第一分支就跳过其余。仓位从零开始，又没有任何代码让它变成非零，于是**账本永久是平的**。每一个"持仓"都是想象的。每一笔成交只动现金：买入扣钱，卖出按当时的价格把钱加回来。闪崩场景 +26.55% 的"利润"是把从未持有过的东西卖进崩盘的产物。净值曲线是小说。

**Bug 2。** 减仓分支末尾的翻转检测按**来单方向**判断：

```python
elif (self.quantity > 0 and signed_qty < 0) or ...:
    self.avg_price = price   # 本意只处理翻向
```

任何部分减仓——多 20 股、卖 15 股、还剩多 5 股——都会触发这一行，把 `avg_price` 覆盖成成交价。而真正的翻向（净空头）反而两个条件都不满足，留下陈旧的成本价。已实现盈亏在每次部分平仓时漂移。正确做法是比较成交前后仓位的符号。

**Bug 3，潜伏的。** 净值公式是 `cash + quantity × mark + realized_pnl`。现金已经包含每笔成交的现金流——含实现过往盈亏的卖出所得——再加 `realized_pnl` 等于把平仓结果算两遍。Bug 1 把它遮得严严实实：仓位永久为零，已实现盈亏就永久为零（这也是为什么 359 笔成交之后它精确读出 `0.0`——这个破绽我本该第一个注意到）。

同一次审计还揪出三个较小的缺陷：波动率目标用的是*组合*收益——账本（本应开仓）平时，它趋零，让仓位和市场风险脱钩——现在改为引用资产收益；Sortino 分母可能退化到接近零，打印出 -22,090,555.249 这种数字（真实输出，seed 42）；以及上面说的年化口径错位。全部修复，全部已提交。

Seed 7，其余一切相同：

|------|--------------------|--------------|----------------|--------------|---------------|---------------|

每个数字都变了性质。修复前那行"崩盘里赚钱"蒸发了——那是靠卖出不存在的股份制造的。修复后这行是四小亏加一个掷硬币，这正是没有优势的玩具信号该有的产出。

## 经济学：成本精确到分

修复后，seed 7 基线：484 笔成交，成交名义额 $930,813，最终盈亏 **-$465.60**。

现在算账。回合的每一侧付半个 5bps 价差加 2bps 滑点——每侧约 4.5bps，再加佣金：

- 价差 + 滑点：$930,813 × 4.5bps ≈ **$418.87**
- 佣金：**$47.01**
- 估算总成本：**$465.88**

估算成本 $465.88，实际 -$465.60。误差二十八美分。这些策略五千分钟的合成毛优势约等于零——所以盈亏*就是*成本结构。这是我能给出的最干净的交易成本经济学演示：零 alpha 不意味着零盈亏，它意味着你的盈亏等于你的交易成本，且可靠得像数学。

四个种子讲同一个故事——这不是运气：

|------|--------|----------|------|--------|----------|------|
| 7 | -0.47% | -0.48% | 46.9% | 0.81 | 484 | $47.01 |
| 21 | -0.49% | -0.49% | 47.1% | 0.80 | 484 | $46.99 |

低方差、持续小亏。教科书级的成本磨损签名。

## 压力测试：稳健性标尺

修复后的场景分析（每场景 2,000 分钟）：

| 场景 | 波动 / 漂移 | Sharpe | 收益 | 最大回撤 | 胜率 |
|------|-------------|--------|------|----------|------|
| 低波牛市 | 15% / +10% | -32.7 | -0.26% | -0.29% | 45.2% |
| 正常 | 20% / +5% | -35.0 | -0.31% | -0.33% | 46.0% |
| 高波熊市 | 40% / -15% | -13.0 | -0.18% | -0.24% | 49.9% |
| 崩盘 | 60% / -30% | +0.09 | +0.04% | -0.18% | 48.9% |
| 闪崩 | 80% / -10% | -8.1 | -0.17% | -0.27% | 48.2% |

两层解读。第一，波动率目标在干活：仓位标量是 0.15/σ，场景波动率翻倍、敞口就减半——这就是为什么高波动场景的绝对磨损反而*更小*，也是为什么所有场景的最大回撤都钉死在 10% 节流线以内。

第二，Sharpe 那列看起来很怪（平静市场里 -32？），直到你想明白它在度量什么：近乎确定性的成本磨损几乎没有方差，而 Sharpe 除以的就是那个接近零的数。这个指标如实描述了收益流的形状——缓慢滴血——尽管"Sharpe -32"读起来像灾难，实际亏损只有 26 个基点。这里的年化数字还把 2,000 分钟外推到一整年，这本身就是需要注明的口径。当指标和量级打架时，第一步是搞清为什么，第二步是把两个都报出来。

而按模拟器自己立的标准——*所有*场景风险调整后为正——五场里挂了四场。这些信号不可交易。模拟器这么说，而我信了，因为产出这些数字的账目是我亲手审计过的。

## 这和 Jane Street 有什么关系

我认为是一切。这家公司的面试就建立在"如果……会发生什么"之上——如果两笔订单同价到达、如果盘口交叉、如果你的模型输入过期了会怎样。这些问题是心智模型的单元测试，答得好的候选人是那些维护不变量的人：现金守恒、账本间一致、能在边界情况里活下来的符号约定。我的模拟器通过了所有目视检查——曲线合理、场景故事讲得通——而它的仓位账本在结构上是空的。抓住它的是一次手工算术的单元探测，和一个与假设矛盾的特征（已实现盈亏恰好是 0.0）。

Jane Street 的工程文化痴迷的正是这一类失败。Signals & Threads 的 "Why Testing is Hard and How to Fix it with Will Wilson" 一期讲的是让测试强到能抓住 code review 漏掉的东西；他们博客的 "The Joy of Expect Tests" 一文主张测试应该展示代码的完整行为，而非只给通过/失败。搭这台模拟器把这些从抽象欣赏变成了疤痕组织。一份没有审计过的回测是你讲给自己听的故事。审计——让现金对持仓对净值三账相符、检查不变量、单元探测状态迁移——才是真正的工作。
